## The short version

An LLM asked for a beta will give you one. It will be a number, formatted like
a number, delivered with the same confidence as a correct one. It will
sometimes be right. That "sometimes" is the whole problem, because a number
you have to check by hand is not worth having.

Econometrica takes the arithmetic away from the model. Models decide *what to
compute*. A registry of 37 typed, versioned, unit-tested functions does the
computing. Every figure a user sees traces back to one of those functions and
carries a manifest that reproduces it.

That single decision is what all the rest of this documentation is about: the
shape it forces on the product, the architecture it implies, the things it
makes impossible, and the things it makes possible that were not before.

## Where the source of truth is

This documentation explains the system. It does not replace these:

| File | What it is |
|---|---|
| [`CLAUDE.md`](../CLAUDE.md) | Working notes. Every sharp edge found the hard way, with the probe output that found it. The most useful file in the repository if you are about to change something. |
| [`docs/plans/`](plans/) | The dated design and step plans, one per phase and per feature. These are the record of what was decided and when. |
| The tests | 1,492 backend, 326 frontend, 6 end to end. Where the documentation and the tests disagree, the tests are right. |

## A note on the diagrams

Most of them are [Mermaid](https://mermaid.js.org/), rendered by GitHub from
the source in the Markdown. That is deliberate. A diagram that lives next to
the prose it explains is a diagram that gets updated when the prose does, and
one that lives in a design tool does not.

The six section heroes are SVG, generated by
[`assets/build_doc_diagrams.py`](assets/build_doc_diagrams.py) from a single
definition into a light and a dark file, because hand-maintaining two copies
of a drawing is how they drift apart. Regenerate them with:

```bash
uv run python docs/assets/build_doc_diagrams.py
```
